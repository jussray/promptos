# PromptOS

PromptOS is a governed founder-intent operating system that turns natural-language goals into reusable prompts, workflows, skills, agents, and execution requests without silently changing the founder's intent or authority.

## What PromptOS does

- Converts founder intent into structured instructions with explicit context, constraints, authority, verification, rollback, and stop conditions.
- Preserves approved prompts and workflows as reusable operating assets instead of disposable chat text.
- Keeps prompt, workflow, skill, and agent behavior portable across supported AI providers.
- Distinguishes advisory instructions from execution authority and deployment proof.
- Supports human-reviewed learning and versioned operating patterns.

## Who it is for

PromptOS is designed for founders and small teams who want AI instructions to become durable operating assets while preserving human intent, privacy, provenance, and control.

## Public truth boundary

PromptOS governs instructions. A generated prompt, workflow, skill, plugin declaration, or mission is not by itself authorization to execute, deploy, publish, spend money, send external communications, or modify provider state.

Use the evidence ladder:

current source -> executable contract -> exact-head checks -> provider/runtime evidence -> claim

`VERIFIED`, `INFERRED`, `UNKNOWN`, and `BLOCKED` must remain distinct.

## Relationship to Chief AI and Founder Control Room

PromptOS structures founder intent and reusable operating instructions. Chief AI consumes structured intent for governed reasoning and bounded execution planning. Founder Control Room remains the portfolio governance, approval, execution, and evidence authority.

## Public surfaces

PromptOS has a separately governed GitHub Pages publication capability. ChatGPT Sites is a different provider surface and its PromptOS Site identity is currently unverified in repository evidence.

No ChatGPT Site hostname, slug, custom domain, or publication state should be guessed.

## Content safety rule

A public PromptOS surface must exclude provider credentials, API keys, raw private prompts, private model responses, private workflow logs, proprietary prompt content, and governance-only material.
